# C++ Data-Driven Runtime Tool System

## 1. 프로젝트 소개

이 프로젝트는 DirectX11 기반 3D 팀 프로젝트에서 구현한 **C++ 데이터 기반 런타임 객체 관리 및 내부 편집 툴 시스템**입니다.

원본 프로젝트는 3D 액션 게임 형태로 제작되었지만, 본 문서에서는 게임 연출 결과보다 내부 구현 구조에 초점을 맞춥니다.

제가 담당한 부분은 런타임에서 반복적으로 생성·갱신·삭제되는 객체들을 관리하고, 이를 내부 편집 툴에서 생성·수정·저장·로드할 수 있도록 만든 시스템입니다.

핵심 구조는 다음과 같습니다.

* ImGui 기반 내부 편집 툴
* JSON 기반 데이터 저장/로드
* 런타임 객체 생성 및 생명주기 관리
* Prototype 기반 객체 생성 구조
* Object Pool 기반 객체 재사용
* Manager 계층을 통한 데이터 로드 및 생성 API 제공
* Group 구조를 통한 여러 객체의 순차 실행 제어
* 실시간 상태 갱신 및 버퍼 데이터 처리

즉, 단순히 화면에 보이는 기능을 구현한 것이 아니라,
**편집 툴 → 데이터 저장 → 런타임 로드 → 객체 생성 → 실행 관리 → 재사용**으로 이어지는 데이터 중심 실행 파이프라인을 구현했습니다.

## 3. 담당 역할

이 프로젝트에서 저는 반복적으로 생성되는 런타임 객체를 데이터 기반으로 관리하기 위한 시스템을 담당했습니다.

주요 구현 범위는 다음과 같습니다.

* ImGui 기반 내부 편집 툴 구현
* 편집 데이터의 JSON 저장/로드 구조 구현
* 런타임 객체 생성 Manager 구현
* Prototype 기반 객체 생성 구조 연동
* Object Pool 기반 객체 재사용 구조 연동
* 여러 객체를 시간 기준으로 실행하는 Group 시스템 구현
* 객체별 Transform, 상태, 수명, 실행 여부 관리
* 실시간 데이터 갱신 구조 구현
* DirectX11 버퍼 및 셰이더 리소스 기반 렌더링 데이터 처리

## 4. 시스템 구조

```text
Internal Tool
 ├─ Object Edit UI
 ├─ Resource List
 ├─ Transform Gizmo
 ├─ Runtime Preview
 └─ JSON Save / Load

Data Layer
 ├─ JSON Object Data
 ├─ JSON Group Data
 └─ Resource Path Data

Runtime Layer
 ├─ Object Prototype
 ├─ Object Pool
 ├─ Object Manager
 ├─ Group Executor
 └─ Runtime Object Instance

Execution Flow
 ├─ Load JSON Data
 ├─ Register Prototype
 ├─ Register Object Pool
 ├─ Create Runtime Object
 ├─ Update Object State
 ├─ Execute Group Timeline
 └─ Return Object to Pool
```

전체 흐름은 다음과 같습니다.

1. 내부 편집 툴에서 객체 속성값을 수정합니다.
2. 수정한 데이터를 JSON으로 저장합니다.
3. 런타임에서 JSON 데이터를 로드합니다.
4. 로드된 데이터를 기반으로 Prototype을 등록합니다.
5. 반복 생성되는 객체는 Object Pool에 등록합니다.
6. 런타임 로직에서 Manager를 통해 객체를 생성합니다.
7. 객체는 상태, 수명, Transform, 실행 조건에 따라 갱신됩니다.
8. 여러 객체는 Group 구조를 통해 시작 시간 기준으로 순차 실행됩니다.
9. 실행이 끝난 객체는 제거되거나 Object Pool로 반환됩니다.

## 5. 핵심 구현 1: ImGui 기반 내부 편집 툴

### 개요

ImGui 기반으로 런타임 객체를 생성하고 수정할 수 있는 내부 편집 툴을 구현했습니다.

툴에서는 객체 타입별 편집 탭을 제공하고, 각 객체의 속성값을 UI에서 직접 수정할 수 있도록 구성했습니다.

지원한 주요 기능은 다음과 같습니다.

* 객체 생성 / 삭제
* 객체 데이터 저장 / 로드
* 텍스처 및 모델 리소스 선택
* 리소스 검색
* 리소스 미리보기
* Transform 수정
* 실시간 프리뷰
* 여러 객체를 묶는 Group 편집
* Group 내 객체 시작 시간 조정
* 기존 Group 내 객체 재수정

### 문제

객체의 속성값을 코드에서 직접 수정하는 방식은 반복 작업이 많고, 원하는 결과를 빠르게 확인하기 어렵습니다.

특히 위치, 크기, 회전, 색상, 수명, 이동 방식, 리소스 경로, 실행 조건처럼 조정해야 할 값이 많을수록 코드 수정과 빌드 반복이 비효율적입니다.

### 해결

ImGui 기반 내부 편집 툴을 구현하여 객체의 속성값을 UI에서 직접 수정하고, 변경된 값을 런타임 객체에 즉시 반영하도록 구성했습니다.

또한 ImGuizmo를 연동하여 객체의 위치, 회전, 크기를 화면에서 직접 조작할 수 있도록 만들었습니다.

### 결과

코드 수정 없이 객체 데이터를 생성, 수정, 저장, 로드할 수 있는 내부 제작 환경을 만들었습니다.

이를 통해 데이터 수정과 결과 확인 사이의 반복 비용을 줄이고, 런타임 객체를 데이터 기반으로 관리할 수 있는 구조를 구성했습니다.

## 6. 핵심 구현 2: JSON 기반 데이터 저장/로드

### 개요

툴에서 편집한 객체 데이터를 JSON으로 저장하고, 런타임에서 다시 로드하여 객체 생성과 동작 설정에 사용할 수 있도록 구현했습니다.

저장되는 데이터는 객체 타입에 따라 다르지만, 공통적으로 다음과 같은 정보를 포함합니다.

* 객체 타입
* 리소스 이름 또는 경로
* Transform
* 수명
* 실행 조건
* 색상
* 속도
* 상태 변화 값
* 셰이더 패스 또는 처리 타입
* Group 내 시작 시간
* Object Pool 생성 개수

### 문제

객체 속성값이 코드에 직접 포함되어 있으면, 값을 수정할 때마다 코드를 변경하고 다시 빌드해야 합니다.

또한 여러 객체를 조합한 복합 실행 구조에서는 각 객체의 시작 시간, 위치, 타입, 파일 경로 등을 일관되게 저장하고 복원할 방법이 필요했습니다.

### 해결

객체별 Write / Load 함수를 구현하여 런타임 객체의 설정값을 JSON으로 직렬화하고, 다시 역직렬화할 수 있도록 구성했습니다.

단일 객체 데이터와 Group 데이터를 분리하여 저장하고, 런타임 로드 시 단일 객체 데이터를 먼저 등록한 뒤 Group 데이터를 로드하도록 처리했습니다.

### 결과

툴에서 만든 데이터를 런타임에서 그대로 재사용할 수 있게 되었고, 객체 생성과 동작 설정을 코드가 아니라 데이터 중심으로 제어할 수 있었습니다.

## 7. 핵심 구현 3: Manager / Prototype / Object Pool 구조

### 개요

런타임 객체 데이터를 로드하고 생성하기 위한 Manager 구조를 구현했습니다.

Manager는 데이터 폴더를 순회하여 JSON 파일을 읽고, 객체 타입에 따라 Prototype을 등록한 뒤, 반복 생성이 필요한 객체는 Object Pool에 연결합니다.

### 문제

실시간 실행 환경에서는 짧은 시간 동안 많은 객체가 반복적으로 생성되고 사라질 수 있습니다.

이때 매번 동적 할당과 해제를 반복하면 객체 생명주기 관리가 복잡해지고, 런타임 안정성에도 부담이 될 수 있습니다.

### 해결

JSON 데이터 로드 시 각 객체를 Prototype으로 등록하고, 설정된 풀 개수에 따라 Object Pool을 생성하도록 구성했습니다.

런타임에서 객체가 필요할 때는 Manager를 통해 Object Pool에서 객체를 가져오고, 사용이 끝난 객체는 제거하거나 풀로 반환할 수 있도록 했습니다.

### 결과

반복 생성되는 객체를 재사용할 수 있는 구조를 만들었고, 객체 생성 로직을 Manager 계층으로 분리하여 런타임 로직이 구체적인 생성 과정을 몰라도 객체를 사용할 수 있게 했습니다.

## 8. 핵심 구현 4: Group 기반 순차 실행 시스템

### 개요

여러 개별 객체를 하나의 Group으로 묶고, 각 객체의 시작 시간을 기준으로 순차 실행하는 Group 시스템을 구현했습니다.

Group은 내부에 여러 객체 데이터를 가지고 있으며, 각 객체는 다음 정보를 포함합니다.

* 객체 포인터
* 객체 타입
* 파일 경로
* 파일 이름
* 시작 시간
* 로컬 Transform
* 종료 여부

### 문제

복합 동작을 구성할 때 여러 객체를 각각 코드에서 생성하고, 타이머로 실행 시점을 맞추면 관리가 복잡해집니다.

또한 여러 객체의 상대 위치와 실행 순서를 하나의 단위로 저장하고 재사용할 방법이 필요했습니다.

### 해결

Group 내부에 객체 목록을 저장하고, 매 프레임 누적 시간과 각 객체의 시작 시간을 비교하여 실행 시점이 된 객체를 활성화하도록 구현했습니다.

또한 Group Transform과 하위 객체의 로컬 Transform을 조합하여, Group 전체를 이동해도 내부 객체들의 상대 배치가 유지되도록 구성했습니다.

### 결과

여러 객체를 시간차로 실행하는 복합 동작을 데이터로 구성할 수 있게 되었습니다.

툴에서 Group을 구성하고 JSON으로 저장하면, 런타임에서 동일한 실행 순서와 배치로 재사용할 수 있습니다.

## 9. 핵심 구현 5: 실시간 상태 갱신 및 버퍼 데이터 처리

### 개요

런타임 객체는 매 프레임 위치, 크기, 회전, 색상, 수명, 실행 상태 등의 데이터를 갱신합니다.

일부 객체는 DirectX11의 버퍼를 사용하여 다수의 데이터를 한 번에 처리하거나, 동적으로 변하는 정점 데이터를 갱신하도록 구현했습니다.

### 구현 예시 1: Instancing Buffer 기반 다중 객체 데이터 처리

여러 개의 작은 객체 상태를 개별 오브젝트로 관리하는 대신, 하나의 객체 내부에서 per-instance 데이터를 관리하도록 구성했습니다.

각 인스턴스는 다음 데이터를 가집니다.

* 위치
* 크기
* 회전
* 색상
* 수명
* 이동 방향
* 인덱스 정보

이를 버퍼에 갱신하고 일괄 처리하여 다수의 객체 상태를 관리했습니다.

### 구현 예시 2: Dynamic Vertex Buffer 기반 실시간 메시 갱신

움직이는 오너 객체를 따라가며 매 프레임 정점 데이터를 갱신하는 구조를 구현했습니다.

오래된 정점은 제거하고 새로운 정점을 추가하며, 보간을 적용해 부드러운 데이터 흐름을 만들었습니다.

### 결과

런타임에서 계속 변화하는 데이터를 갱신하고, 객체별 상태 변화를 실시간으로 반영할 수 있었습니다.

## 11. 일반 소프트웨어 개발 관점에서의 의미

이 프로젝트는 게임 프로젝트에서 출발했지만, 내부 구조는 일반 소프트웨어 개발에서도 의미 있는 요소를 포함합니다.

### 내부 툴 개발

ImGui 기반 편집 툴을 통해 사용자가 데이터를 직접 조정하고 즉시 결과를 확인할 수 있는 환경을 구현했습니다.

이는 사내 운영 툴, 디버깅 툴, 시각화 툴, 데이터 편집 툴 개발 경험으로 확장해서 설명할 수 있습니다.

### 데이터 기반 설계

객체의 동작을 코드에 고정하지 않고 JSON 데이터로 분리했습니다.

이는 설정 기반 시스템, 룰 기반 실행 구조, 데이터 중심 애플리케이션 구조와 연결됩니다.

### 객체 생명주기 관리

반복 생성되는 객체를 Manager와 Object Pool을 통해 관리했습니다.

이는 서버, 시뮬레이션, 실시간 처리 시스템, 리소스 관리 시스템에서 중요한 객체 생명주기 관리 경험으로 설명할 수 있습니다.

### 런타임 로드 구조

파일 시스템을 순회하여 데이터 파일을 읽고, 타입별로 Prototype을 등록하는 구조를 구현했습니다.

이는 플러그인 구조, 설정 파일 기반 초기화, 리소스 로더, 데이터 파이프라인 경험으로 설명할 수 있습니다.

### 실시간 상태 갱신

## 14. 개선 가능성

이 프로젝트를 다시 설계한다면 다음 부분을 개선할 수 있습니다.

* 데이터 변경 감지 기반 Hot Reload 구조 개선

## 15. 프로젝트를 통해 배운 점

이 프로젝트를 통해 단순히 결과물을 화면에 출력하는 것보다, 데이터를 제작하고 재사용할 수 있는 구조를 만드는 것이 중요하다는 점을 배웠습니다.

초기에는 개별 객체 구현에 집중했지만, 프로젝트가 진행되면서 속성값을 빠르게 조정할 수 있는 툴, 데이터를 저장하고 다시 불러오는 구조, 런타임에서 데이터를 기반으로 객체를 생성하는 Manager 구조, 반복 생성되는 객체를 재사용하는 Object Pool 구조가 필요하다는 것을 느꼈습니다.

그 결과 단일 기능 구현에서 끝나지 않고,
**내부 편집 툴 → JSON 데이터 → 런타임 로드 → 객체 생성 → 그룹 실행 → 오브젝트 풀 재사용**으로 이어지는 데이터 기반 실행 파이프라인을 구성했습니다.

이 경험을 통해 C++ 객체지향 설계, 데이터 직렬화, 내부 툴 제작, 런타임 객체 관리, 객체 생명주기 관리, 실시간 상태 갱신에 대한 이해를 쌓을 수 있었습니다.

## 16. 요약

이 프로젝트는 DirectX11 기반 게임 프로젝트에서 구현한 기능이지만, 핵심은 게임 연출 자체보다 **C++로 데이터 기반 툴과 런타임 객체 관리 시스템을 설계하고 구현한 경험**입니다.

툴에서 데이터를 편집하고, JSON으로 저장한 뒤, 런타임에서 로드하여 객체를 생성하고, Object Pool과 Group 시스템을 통해 실행과 생명주기를 관리하는 구조를 만들었습니다.

이를 통해 C++ 객체지향 설계, 데이터 직렬화, 내부 툴 제작, 런타임 객체 관리, 객체 재사용, 실시간 상태 갱신에 대한 실무형 경험을 쌓을 수 있었습니다.
